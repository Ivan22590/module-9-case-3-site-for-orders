Техническое задание на разработку кейса ↘️

Практический кейс по созданию сайта для обработки заказов от покупателей. В этой части мы сделаем MVP нашего продукта, организуем сбор данных, настроим API и развернём приложение.

Будем стараться работать в парадигме “докеризированного монолита” — всё будем делать в одном контейнере.

Цель: развернуть единый веб-стек на одном виртуальном сервере для безопасного приёма и обработки заявок от клиентов.

Инфраструктурная модель:

Один виртуальный сервер — единая площадка для всего контура;
Backend работает в Docker-контейнерах с автодеплоем;
Frontend разворачивается через Nginx и является входной точкой трафика;
Внешний мир (боты, люди) видит только Nginx, IP и домен сервера → всё остальное закрыто в локальной сети сервера;
Backend не доступен извне: только локальные запросы от фронта внутри машины, что обеспечит безопасность работы базы данных;
Вся коммуникация Frontend → Backend идёт через Nginx, безопасно и без утечек наружу.

Функциональный контур сайта:
Страница для "тёплых клиентов", где заполняется форма заявки (контактные данные, клиентские запросы);
Поля: контактные данные, информация о бизнесе, бюджет, удобный способ связи, комментарии;
Скрипты фронта автоматически агрегируют и анилизируют лид-метрики и техническую информацию;
Frontend собирает всё в единый пакет данных и отправляет в Backend для записи.

Хранилище:
Серверная БД локально внутри той же машины (на основе PostgreSQL);
Доступ к базе — только через Backend;
Все данные хранятся и обрабатываются строго внутри контура.

Требования по безопасности:
Внешний запрос к Backend невозможен;
Доступ к API только через Frontend, только через Nginx;
Контейнеры изолированы.
Данные клиентов не покидают сервер.
